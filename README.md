# Этап 5. Визуализация графа зависимостей

Программа строит транзитивный граф рекурсивным DFS, печатает D2, сохраняет SVG
и открывает изображение стандартным браузером. По флагу выводится ASCII-дерево.
Для получения зависимостей используются только стандартные библиотеки Python.

## Версии только реальных пакетов

В D2, SVG и ASCII возле каждого реального пакета выводится версия из `info.version`
того же ответа JSON API, по которому прочитаны его зависимости. Дополнительного запроса нет.
Это версия исследованных метаданных, а не установленного на компьютере пакета.
Если API не передал версию, выводится `версия не указана` — номер не выдумывается.

В режиме `--test-repo` остаются обычные подписи `A`, `B`, `C`, без версий.
Версии добавлены только в эту ветку: этапы 1–4 не изменены.

## Требования и запуск

Python 3.10 или новее и браузер для SVG. Сторонние Python-библиотеки не нужны.
D2 формируется как текст; SVG рисуется собственным кодом из того же графа,
а не внешним D2-компилятором. Установка D2 и Graphviz не требуется.

Откройте терминал в папке проекта и выполните:

```sh
python src/main.py --package A --repository examples/diamond.json --test-repo --ascii-tree
```

В Windows также можно выполнить `run.bat` с теми же аргументами.
В Linux/macOS используйте `python3` или `sh run.sh`.
Справка: `python src/main.py --help`.

В `output/` сохраняются `A.d2` и `A.svg`. Изображение открывается браузером.
Ребро направлено от пакета к его зависимости; общая вершина изображается один раз.
Файлы выбранного корня перезаписываются при повторном запуске.

```text
A
|-- B
|   `-- D
`-- C
    `-- D [повтор]
```

Без `--ascii-tree` дерево не печатается. Повтор на активном пути отмечается `[цикл]`,
а уже раскрытая общая зависимость — `[повтор]`. Циклические рёбра сохраняются в D2 и SVG.
Порядок загрузки этапа 4 и отладочная конфигурация этапа 1 здесь не выводятся.

## Параметры

- `--package`: обязательное имя корневого пакета.
- `--repository`: обязательный адрес JSON API либо путь к тестовому JSON.
- `--test-repo`: читать локальный JSON с именами из заглавных латинских букв.
- `--filter`: исключить имена по подстроке без учёта регистра.
- `--ascii-tree`: дополнительно вывести дерево.

Запрашивается `<адрес>/<имя>/json`. Для `https://pypi.org` автоматически добавляется `/pypi`.
HTML-индекс `/simple` не поддерживается. Имена реальных пакетов нормализуются.
Тестовый JSON проверяется целиком: все цели рёбер должны присутствовать среди ключей.

## Реальные пакеты

Для публичного репозитория:

```sh
python src/main.py --package python-dateutil --repository https://pypi.org/pypi --ascii-tree
python src/main.py --package six --repository https://pypi.org/pypi --ascii-tree
python src/main.py --package pytz --repository https://pypi.org/pypi --ascii-tree
python src/main.py --package Jinja2 --repository https://pypi.org/pypi --ascii-tree
```

Команды собраны в `scripts/demo_real.bat` и `scripts/demo_real.sh`.
Для повторяемой демонстрации без внешнего интернета в первом терминале выполните:

```sh
python -m http.server 8000 --bind 127.0.0.1 --directory examples/pypi
```

Во втором терминале используйте тот же пакет с локальным адресом, без `--test-repo`:

```sh
python src/main.py --package Jinja2 --repository http://127.0.0.1:8000 --ascii-tree
```

Снимок дополнительного примера даёт четыре вершины и три ребра:

```text
jinja2 (3.1.6)
|-- babel (2.9.1)
|   `-- pytz (2026.4)
`-- markupsafe (3.0.3)
```

Babel объявлен Jinja2 для дополнительной группы `i18n`, а не как обязательная зависимость
обычной установки. Программа, как и раньше, извлекает все объявления `requires_dist`,
не вычисляя extras и маркеры окружения. Версия Babel зафиксирована для небольшого графа;
текущие публичные версии и их зависимости могут отличаться.

Для исходных снимков python-dateutil 2.9.0.post0 зависит от six 1.17.0;
у six и pytz 2026.4 нет зависимостей. Источник всех снимков, включая публичные поля Babel,
описан в `examples/metadata-origin.md`. Это сокращённые поля, а не полные ответы PyPI.

## Тестовые случаи и сравнение

В `examples/` находятся одиночный пакет, цепочка, ромб, цикл, петля и несвязанные компоненты.
Сценарии: `scripts/demo.bat`, `sh scripts/demo.sh`; ошибочные параметры — `scripts/errors.*`.
Фильтрация применяется до визуализации; при исключении корня сохраняется пустой граф с пояснением.

У pip нет встроенной команды рисования графа. В `COMPARISON.md` сопоставлены исходные три
графа с нативным `pip inspect` для тех же версий и объяснены отличия.
Программа не вызывает pip для получения зависимостей, не устанавливает и не импортирует пакеты,
не разрешает ограничения версий. Это граф объявлений, а не полноценная замена pip.

## Проверка и ошибки

```sh
python -m unittest discover -s tests -v
python tests/check_style.py
```

Пройдены 72 теста и проверка измеримых ограничений. Проверяются также версии в D2/SVG/ASCII,
отсутствие версий у тестовых букв, кэш, фильтрация, циклы, запись файлов и вызов браузера.
Автотесты работают без внешнего интернета и не открывают окон.
Четыре реальные демонстрации выполнены через локальный HTTP; SVG отрисованы Chromium.

Коды: 0 — успех, 1 — ошибка данных/сети/записи/браузера, 2 — неверные параметры.
HTTP-ответ ограничен 8 МиБ, время запроса — 15 секундами; глубокая рекурсия обрабатывается.
При ошибке браузера SVG остаётся на диске: откройте его вручную.
Внешний DNS в проверочной среде недоступен: живой запуск с публичным PyPI здесь не проверен.
Нативный браузер Windows и внешний D2-компилятор в этой среде не проверялись.

## Файлы

- `src/config.py`: параметры и их проверка.
- `src/repository.py`: HTTP, объявления зависимостей, версии и кэш.
- `src/local_repository.py`, `src/graph.py`: тестовые данные и рекурсивный DFS.
- `src/package_labels.py`: подписи с версиями для реальных пакетов.
- `src/d2_format.py`, `src/ascii_tree.py`: D2 и дерево.
- `src/svg_layout.py`, `src/svg_format.py`: координаты и SVG.
- `src/visualization.py`, `src/main.py`: сохранение, открытие изображения и запуск.
- `examples/`, `tests/`, `scripts/`: данные, проверки и демонстрации.

Папка `output/`, архивы, PDF, кэш и файлы IDE исключены из Git.
