# Визуализатор графа зависимостей Python-пакетов

Практическая работа № 2 по конфигурационному управлению.

Консольная программа получает сведения о зависимостях Python-пакетов из JSON API
репозитория или локального тестового файла. Для получения данных используются
стандартная библиотека Python и собственный код, без вызова менеджеров пакетов
и готовых библиотек получения зависимостей.

## Состав работы

| Этап | Содержание | Состояние |
|---|---|---|
| 1 | Параметры CLI, проверка ошибок и вывод конфигурации | Реализован |
| 2 | Получение прямых зависимостей из JSON API | Реализован |
| 3 | Транзитивный граф, рекурсивный DFS, фильтр, циклы и тестовый режим | Реализован |
| 4 | Порядок загрузки зависимостей и сравнение с менеджером пакетов | Не реализован |
| 5 | Представление графа на D2, изображение и ASCII-дерево | Не реализован |

Код этапов находится в ветках `stage-1`, `stage-2` и `stage-3`.
Ветки `stage-4` и `stage-5` содержат только пустой служебный файл `.gitkeep`.
Ветка `main` содержит общую документацию. Разделы 4–5 ниже описывают требования
задания, а не возможности опубликованной программы.

## Этап 1. Минимальный CLI и конфигурация

### Реализованные возможности

- Приём имени анализируемого пакета.
- Приём URL репозитория или пути к локальному тестовому файлу.
- Выбор тестового режима.
- Приём флага ASCII-дерева и подстроки исключаемых пакетов.
- Проверка параметров и вывод диагностических сообщений.
- Вывод всех пяти настроек в формате `ключ=значение`.

На этом этапе сетевые запросы, чтение структуры тестового графа и построение
графа не выполняются. Файл тестового репозитория не изменяется.
Фильтр и флаг ASCII-дерева только сохраняются в конфигурации.

### Параметры командной строки

| Параметр | Назначение |
|---|---|
| `--package` | Обязательное имя анализируемого пакета |
| `--repository` | Обязательный URL JSON API или путь к тестовому файлу |
| `--test-repo` | Использование локального тестового репозитория |
| `--ascii-tree` | Выбор режима ASCII-дерева; в этапах 1–3 дерево не строится |
| `--filter` | Подстрока исключаемых пакетов; по умолчанию пустая |

Флаги `--test-repo` и `--ascii-tree` передаются без значений.
Пути с пробелами необходимо заключать в двойные кавычки.
В тестовом режиме имена пакетов состоят из заглавных латинских букв A–Z.

### Для проверки

В ветке `stage-1` выполните:

```powershell
python src/main.py --package requests --repository https://pypi.org/pypi
```

Ожидаемый вывод:

```text
package=requests
repository=https://pypi.org/pypi
test_repo=False
ascii_tree=False
filter=
```

Проверка всех параметров:

```powershell
python src/main.py --package A --repository examples/repository.json --test-repo --ascii-tree --filter B
```

Проверяются следующие ошибки:

- Отсутствие обязательного имени пакета или адреса репозитория.
- Недопустимое имя пакета, например `--package "bad name"`.
- Неподдерживаемый URL, например `--repository ftp://host`.
- Несуществующий тестовый файл при использовании `--test-repo`.
- Передача значения флагам, например `--test-repo=maybe` или `--ascii-tree=maybe`.
- Отсутствие значения после `--filter` или фильтр, состоящий только из пробелов.

Готовые примеры: `scripts/demo.bat` и `scripts/errors.bat`.
В Linux/macOS: `sh scripts/demo.sh` и `sh scripts/errors.sh`.

## Этап 2. Получение прямых зависимостей

### Реализованные возможности

- Загрузка метаданных Python-пакета через HTTP(S) JSON API.
- Чтение объявлений зависимостей из поля `info.requires_dist`.
- Вывод всех прямых объявленных зависимостей.
- Сообщение об отсутствии зависимостей.
- Проверка структуры ответа и соответствия имени запрошенного пакета.
- Обработка сетевых ошибок и некорректных данных без traceback.
- Кеширование метаданных в пределах одного запуска.

На этом этапе конфигурация из первого этапа не выводится.
Транзитивный обход не выполняется. Параметры фильтра и ASCII-дерева принимаются,
но не применяются. Чтение локального тестового графа в этой версии не поддерживается:
при `--test-repo` программа выводит диагностическое сообщение и завершается с кодом 1.

### Источник данных

Для официального Python Package Index используется база `https://pypi.org/pypi`.
Для пакета `python-dateutil` запрос направляется по адресу:

```text
https://pypi.org/pypi/python-dateutil/json
```

Адрес `https://pypi.org` также принимается и дополняется путём `/pypi`.
Simple API `/simple` не поддерживается. Другой сервер должен предоставлять
совместимый JSON API с объектом `info`.

Репозиторий пакетов — источник метаданных. Это не GitHub-репозиторий с исходным кодом программы.

### Для проверки

В ветке `stage-2` выполните:

```powershell
python src/main.py --package python-dateutil --repository https://pypi.org/pypi
```

В ответе выводятся объявления прямых зависимостей с ограничениями версий
и маркерами окружения, если они присутствуют в метаданных.
Содержание ответа зависит от актуальных данных сервера.

Пакет без собственных зависимостей:

```powershell
python src/main.py --package six --repository https://pypi.org/pypi
```

Дополнительно проверяются отсутствующий пакет, сетевые ошибки, неверный JSON
и неправильная структура метаданных. Автотесты используют подменённые ответы
и локальный HTTP-сервер, поэтому для их выполнения внешний интернет не требуется.

Сценарии `scripts/demo.bat` и `scripts/demo.sh` демонстрируют запросы
для `requests`, `six` и `peppercorn`. Для обращения к PyPI требуется интернет.

## Этап 3. Построение транзитивного графа

### Реализованные возможности

- Собственный рекурсивный обход в глубину — DFS.
- Поиск прямых и транзитивных зависимостей от выбранного корневого пакета.
- Однократное посещение общей зависимости.
- Исключение пакетов, имена которых содержат заданную подстроку.
- Обработка циклов, включая зависимость пакета от самого себя.
- Чтение локального тестового репозитория из JSON-файла.
- Вывод списка смежности и сообщений о найденных циклических путях.

Направление ребра: `пакет -> его зависимости`.
Результат этого этапа — текстовый список смежности, не изображение и не ASCII-дерево.

### Формат тестового репозитория

Ключ JSON-объекта — имя пакета, значение — список его прямых зависимостей.
Имена состоят из заглавных латинских букв. Каждый упомянутый пакет должен
присутствовать как ключ, даже если у него нет зависимостей.

Пример `examples/diamond.json`:

```json
{
  "A": ["B", "C"],
  "B": ["D"],
  "C": ["D"],
  "D": []
}
```

Повторяющиеся рёбра удаляются. Повторяющиеся ключи, неверные типы данных,
неправильные имена и ссылки на отсутствующие пакеты отклоняются.
Несвязанные с корневым пакетом компоненты не обходятся.

### Для проверки: готовый тестовый репозиторий

В ветке `stage-3` выполните:

```powershell
python src/main.py --package A --repository examples/diamond.json --test-repo
```

Ожидаемый вывод:

```text
A -> B, C
B -> D
C -> D
D -> (нет)
```

Пакет `D` является общей зависимостью `B` и `C`, но посещается один раз.
Интернет для тестового режима не требуется.

### Для проверки: цикл

```powershell
python src/main.py --package A --repository examples/cycle.json --test-repo
```

Ожидаемый вывод:

```text
A -> B
B -> C
C -> A
Цикл: A -> B -> C -> A
```

Ребро цикла сохраняется в графе. Программа завершает обход без зацикливания.
Диагностика показывает обратные рёбра DFS, а не все возможные циклы графа.

### Для проверки: фильтрация

```powershell
python src/main.py --package A --repository examples/diamond.json --test-repo --filter B
```

Ожидаемый вывод:

```text
A -> C
C -> D
D -> (нет)
```

Пакет `B` исключён. Пакет `D` остаётся достижимым через `C`.
Если к потомку ведёт только исключённая ветка, такой потомок не анализируется.
Подстрока проверяется без учёта регистра после нормализации имени.
Исключение корневого пакета даёт пустой граф и диагностическое сообщение.

### Для проверки: собственный тестовый репозиторий

Создайте в каталоге `examples` файл `my_repository.json` в кодировке UTF-8:

```json
{
  "A": ["B", "C"],
  "B": ["D"],
  "C": ["E"],
  "D": ["A"],
  "E": []
}
```

Это пример для самостоятельного создания файла, а не файл из поставки проекта.
При сохранении через Блокнот выберите тип «Все файлы».
Имя файла должно быть `my_repository.json`, без дополнительного расширения `.txt`.

```powershell
python src/main.py --package A --repository examples/my_repository.json --test-repo
```

В графе присутствуют разветвление и цикл `A -> B -> D -> A`.

### Для проверки: реальный репозиторий

```powershell
python src/main.py --package python-dateutil --repository https://pypi.org/pypi
```

Для метаданных, в которых единственная зависимость `python-dateutil` — `six`,
ожидается следующий граф:

```text
python-dateutil -> six
six -> (нет)
```

Флаг `--test-repo` не передаётся. Данные загружаются из PyPI.
Результат зависит от актуальных метаданных пакетов.

### Набор тестовых графов

| Файл в `examples` | Проверяемый случай |
|---|---|
| `single.json` | Один пакет без зависимостей |
| `chain.json` | Цепочка зависимостей |
| `diamond.json` | Общая зависимость нескольких пакетов |
| `cycle.json` | Цикл из трёх пакетов |
| `self_cycle.json` | Зависимость пакета от самого себя |
| `disconnected.json` | Несвязанные компоненты |
| `empty.json` | Пустой репозиторий; выбранный пакет отсутствует |
| `invalid.json` | Ссылка на отсутствующий пакет |

Сценарий `scripts/demo.bat` показывает разные графы, фильтрацию и ошибки тестовых данных.
В Linux/macOS выполните `sh scripts/demo.sh`.

## Особенности анализа и ограничения

- Получение зависимостей выполняется через `urllib`, `json` и собственный код.
- Пакеты не устанавливаются, `pip`, `pipdeptree` и `packaging` не используются для получения данных.
- Читаются все объявления `Requires-Dist`, включая extras и условия окружения.
- Маркеры окружения не вычисляются, ограничения версий не разрешаются.
- Для каждого имени запрашиваются метаданные последней версии пакета.
- Это граф объявленных зависимостей, а не точный состав установки для текущей ОС.
- Один HTTP-ответ ограничен размером 8 МиБ; тайм-аут запроса — 15 секунд.
- Большие графы требуют много запросов. Метаданные кешируются в пределах запуска.
- При превышении глубины рекурсии выводится сообщение об ошибке без traceback.

Сообщение «Ответ репозитория превышает допустимый размер» относится к одному
сетевому ответу, а не к размеру локального тестового JSON-файла.

Коды завершения:

| Код | Значение |
|---|---|
| `0` | Успешное выполнение или вывод справки |
| `1` | Ошибка получения или обработки данных |
| `2` | Ошибка параметров командной строки |

## Структура проекта

Полный набор модулей ниже относится к ветке `stage-3`.
В ветках `stage-1` и `stage-2` находятся только файлы соответствующих этапов.

```text
src/
  config.py             Параметры командной строки и их проверка
  repository.py         Получение метаданных из JSON API
  local_repository.py   Чтение и проверка тестового репозитория
  graph.py              Рекурсивный DFS, фильтрация, циклы и вывод графа
  main.py               Точка входа и обработка ошибок
tests/                  Автотесты и проверка оформления
examples/               Тестовые репозитории
scripts/                Сценарии демонстрации запуска и ошибок
run.bat                 Запуск в Windows
run.sh                  Запуск в Linux/macOS
```

## Подготовка и запуск

Требуется Python 3.10 или новее. Установка сторонних библиотек не нужна.
Это консольное приложение: отдельное графическое окно в этапах 1–3 не открывается.

1. На GitHub выберите ветку нужного этапа: `stage-1`, `stage-2` или `stage-3`.
2. Скачайте её через **Code → Download ZIP** и распакуйте архив.
3. Откройте PowerShell в папке, содержащей `src`, `examples` и `run.bat`.
4. Выполните команду соответствующего этапа из этого документа.

Все пути в примерах указываются относительно корня выбранного этапа.
Запуск `python src/main.py` без обязательных параметров выводит ошибку.

Справка:

```powershell
python src/main.py --help
```

Пример запуска третьего этапа через BAT-файл:

```powershell
.\run.bat --package A --repository examples/diamond.json --test-repo
```

В Linux/macOS используйте `python3` вместо `python` либо выполните:

```sh
sh run.sh --package A --repository examples/diamond.json --test-repo
```

BAT-сценарии демонстрации содержат `pause`, чтобы результаты оставались на экране.

## Автоматические проверки

В корне выбранной ветки `stage-1`, `stage-2` или `stage-3` выполните:

```powershell
python -m unittest discover -s tests -v
python tests/check_style.py
```

Для тестов используется стандартный модуль `unittest`, установка `pytest` не требуется.
Проверяются параметры CLI, обработка ошибок и возможности соответствующего этапа.
Тесты второго и третьего этапов проверяют загрузку метаданных без обращения к внешнему PyPI.
В третьем этапе дополнительно проверяются DFS, общие зависимости, фильтрация,
циклы и формат локального репозитория.

Проверка оформления контролирует измеримые ограничения исходного кода и текстовых файлов.
Она не заменяет проверку функциональных требований задания.
