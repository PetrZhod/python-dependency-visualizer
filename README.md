# Этап 1. Минимальный CLI и конфигурация

Консольная программа принимает пять параметров, проверяет их и выводит конфигурацию
в формате `ключ=значение`. Загрузка зависимостей и построение графа не выполняются.

## Требования

- Python 3.10 или новее.
- Сторонние библиотеки и доступ к интернету не требуются.

## Запуск

Откройте PowerShell в корне проекта, где находятся `src` и `run.bat`, и выполните:

```powershell
python src/main.py --package requests --repository https://pypi.org/pypi
```

Ожидаемый вывод:

```text
package=requests
repository=https://pypi.org/pypi
test_repo=False
ascii_tree=False
filter=
```

Для демонстрации всех параметров выполните:

```powershell
python src/main.py --package A --repository examples/repository.json --test-repo --ascii-tree --filter B
```

При выборе тестового режима файл должен существовать, а имя пакета состоять из букв A–Z.
Содержимое файла на этом этапе не анализируется и не изменяется.
Параметры фильтрации и ASCII-дерева сохраняются в конфигурации без применения к графу.

## Параметры

| Опция | Назначение |
|---|---|
| `--package` | Обязательное имя пакета |
| `--repository` | Обязательный URL JSON API или путь к тестовому файлу |
| `--test-repo` | Флаг выбора тестового репозитория |
| `--ascii-tree` | Флаг выбора режима ASCII-дерева; на этапе 1 выводится только его значение |
| `--filter` | Подстрока исключаемых пакетов; по умолчанию пустая |

Флаги передаются без значений: `--ascii-tree`, а не `--ascii-tree=true`.
Пути с пробелами заключайте в двойные кавычки.

## Демонстрация ошибок

- Отсутствие `--package` или `--repository` — пропущен обязательный параметр.
- `--package "bad name"` — недопустимое имя.
- `--repository ftp://host` — неподдерживаемый URL.
- `--repository missing.json --test-repo` — отсутствующий файл.
- `--test-repo=maybe` — неверное использование флага тестового режима.
- `--ascii-tree=maybe` — неверное использование флага ASCII.
- `--filter` без значения либо `--filter " "` — неверный фильтр.

Для демонстрации корректных настроек запустите `scripts/demo.bat`.
Для демонстрации ошибок запустите `scripts/errors.bat`.
Окна BAT-сценариев остаются открытыми до нажатия клавиши.
В Linux/macOS выполните `sh scripts/demo.sh` или `sh scripts/errors.sh`.

Ошибки параметров завершают программу с кодом 2. Справка и корректный запуск возвращают код 0.

## Справка и проверки

```powershell
python src/main.py --help
python -m unittest discover -s tests -v
python tests/check_style.py
```

В Windows также можно использовать `.\run.bat` с теми же параметрами.
В Linux/macOS используйте `python3` вместо `python` или `sh run.sh` с параметрами.

## Структура проекта

- `src` — исходный код.
- `tests` — автотесты и проверка оформления.
- `examples` — тестовый файл репозитория.
- `scripts` — сценарии демонстрации запуска и ошибок.
- `run.bat`, `run.sh` — запуск программы с переданными параметрами.
