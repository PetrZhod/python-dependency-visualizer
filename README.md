# Этап 2. Получение прямых зависимостей

Реализована загрузка прямых зависимостей Python-пакета из JSON API репозитория.
При запуске выводятся все объявления прямых зависимостей, а не конфигурация этапа 1.
Транзитивный обход относится к этапу 3; визуализация — к этапу 5.

## Демонстрация

```powershell
python src/main.py --package requests --repository https://pypi.org/pypi
```

Программа показывает декларации зависимостей, включая ограничения версий и маркеры.
Состав ответа зависит от текущей версии пакета на сервере.
Для пакета без объявленных зависимостей выводится отдельное сообщение.

Сценарии scripts/demo.bat и scripts/demo.sh запрашивают requests, six и peppercorn.
Для настоящего PyPI нужен интернет. Ошибки параметров показывает scripts/errors.bat.

Фильтр и --ascii-tree принимаются как настройки следующих этапов, но пока не применяются.
При --test-repo программа объясняет, что чтение тестового графа будет добавлено на этапе 3.

## Какие именно зависимости анализируются

Программа читает метаданные последней версии пакета по адресу
`<база JSON API>/<имя>/json`. Для PyPI база — https://pypi.org/pypi.
Короткий адрес https://pypi.org тоже принимается. Simple API /simple не поддерживается.
Другой репозиторий должен предоставлять совместимый JSON API с объектом info.

Поле info.requires_dist содержит декларации Requires-Dist.
Анализируются все объявленные зависимости, включая extras и условия окружения.
Маркеры не вычисляются: это граф деклараций, а не план установки для текущей ОС.
Ограничения версий не разрешаются. Для каждого имени запрашивается последняя версия.
Поэтому результат может отличаться от графа пакетов, реально установленных pip.

Для получения зависимостей используются только urllib, json и собственный код.
Менеджеры пакетов, pipdeptree, packaging и другие сторонние библиотеки не вызываются.
Описание API: https://docs.pypi.org/api/json/.

Ошибки HTTP, DNS, тайм-ауты, чужое имя пакета, неверный JSON и неверный requires_dist
сообщаются без traceback с кодом 1. Ответ ограничен 8 МиБ, тайм-аут — 15 секунд.

## Требования и запуск

Нужен Python 3.10 или новее. Сторонние Python-библиотеки не нужны.
Это консольное приложение, не графическое окно и не эмулятор оболочки.

Открой PowerShell в корне проекта, где находятся src и run.bat.
Справка:

```powershell
python src/main.py --help
```

Проверки:

```powershell
python -m unittest discover -s tests -v
python tests/check_style.py
```

В Linux/macOS используй python3 вместо python либо ./run.sh с параметрами.
В Windows можно использовать .\run.bat с теми же параметрами.

## Параметры

| Опция | Назначение |
|---|---|
| `--package` | Обязательное имя пакета |
| `--repository` | Обязательный URL JSON API или путь к тестовому файлу |
| `--test-repo` | Флаг выбора тестового репозитория |
| `--ascii-tree` | Флаг выбора ASCII-дерева для будущего этапа 5 |
| `--filter` | Подстрока исключаемых пакетов; по умолчанию пустая |

Флаги передаются без значений: --ascii-tree, а не --ascii-tree=true.
Пути с пробелами заключай в двойные кавычки.
Ошибки параметров завершают программу с кодом 2; --help возвращает 0.

## Структура

- src — исходный код.
- tests — автотесты и проверка измеримых ограничений оформления.
- examples — тестовые данные.
- scripts — демонстрации для Windows и Linux/macOS.
- run.bat и run.sh — запуск с переданными пользователем параметрами.

Автоматическая проверка оформления не заменяет официальную проверку преподавателя.
