# Визуализатор графа зависимостей Python-пакетов

Практическая работа № 2 по конфигурационному управлению.
Все пять этапов реализованы в отдельных ветках. Программа получает объявления зависимостей
из JSON API, строит транзитивный граф и формирует его представления.
Для получения зависимостей используются только стандартные библиотеки Python;
готовые менеджеры пакетов и библиотеки анализа зависимостей в программе не вызываются.

## Состав работы

| Этап | Возможности | Ветка |
|---|---|---|
| 1 | Параметры CLI, проверка ошибок, вывод конфигурации | stage-1 |
| 2 | Получение прямых зависимостей из JSON API | stage-2 |
| 3 | Рекурсивный DFS, транзитивность, фильтрация и циклы | stage-3 |
| 4 | Порядок загрузки: зависимости раньше использующих их пакетов | stage-4 |
| 5 | Текст D2, изображение SVG и дополнительное ASCII-дерево | stage-5 |

В `main` находится общая документация. В каждой ветке — самостоятельная версия программы,
тесты, данные, сценарии запуска и README соответствующего этапа.
Вывод конфигурации предусмотрен только этапом 1, прямых объявлений — этапом 2,
порядка загрузки — этапом 4. Этап 5 выводит D2 и показывает изображение.

## Требования и подготовка

- Python 3.10 или новее.
- Для публичного репозитория — интернет и доступ к JSON API.
- Для просмотра изображения этапа 5 — браузер с поддержкой SVG.
- Сторонние Python-библиотеки, Graphviz и компилятор D2 для запуска не требуются.

На странице репозитория выберите нужную ветку, нажмите `Code` → `Download ZIP`
и распакуйте архив. Откройте терминал именно в папке, где находятся `src`, `tests` и `run.bat`.
В Windows можно открыть папку в Проводнике, ввести `cmd` в адресной строке и нажать Enter.

Проверьте Python и справку:

```sh
python --version
python src/main.py --help
```

В Linux/macOS используйте `python3` вместо `python`.
При наличии локального клона переключайте этап командой `git switch stage-1`,
подставляя нужный номер. Команда переключения выполняется из папки репозитория.

## Общие параметры

| Параметр | Назначение |
|---|---|
| --package | Обязательное имя корневого пакета |
| --repository | Обязательный адрес JSON API либо путь к тестовому файлу |
| --test-repo | Читать локальный тестовый JSON вместо HTTP |
| --ascii-tree | Дополнительно показать ASCII-дерево на этапе 5 |
| --filter | Исключить имена с указанной подстрокой без учёта регистра |

Флаги `--test-repo` и `--ascii-tree` не принимают значений `true`, `false` или `maybe`.
Пустой фильтр отключает исключение; одни пробелы и управляющие символы недопустимы.
На этапе 1 параметры только проверяются и выводятся. На этапе 2 фильтр и дерево
ещё не применяются; тестовый режим для получения зависимостей реализован начиная с этапа 3.
На этапе 4 флаг дерева принимается, но дерево выводится только на этапе 5.

Реальные имена состоят из латинских букв, цифр, точек, дефисов и подчёркиваний;
начинаются и заканчиваются буквой или цифрой. Они нормализуются к нижнему регистру,
а группы точек, дефисов и подчёркиваний заменяются дефисом.
Тестовые имена состоят только из заглавных латинских букв, например `A`, `B`, `ABC`.

## Этап 1. Командная строка

Выберите `stage-1`. Выполните:

```sh
python src/main.py --package six --repository https://pypi.org/pypi
```

Результат:

```text
package=six
repository=https://pypi.org/pypi
test_repo=False
ascii_tree=False
filter=
```

Программа проверяет обязательные значения, имя, URL, путь тестового файла,
фильтр, неизвестные опции и недопустимые значения флагов. Сетевые запросы не выполняются.
Для демонстрации всех параметров:

```sh
python src/main.py --package A --repository examples/repository.json --test-repo --ascii-tree --filter B
```

## Этап 2. Прямые зависимости

Выберите `stage-2`. Выполните:

```sh
python src/main.py --package six --repository https://pypi.org/pypi
python src/main.py --package python-dateutil --repository https://pypi.org/pypi
```

Программа стандартным `urllib` получает `<адрес>/<имя>/json`, проверяет объект `info`
и выводит прямые объявления `requires_dist`, включая ограничения версий и условия.
У six в проверенных метаданных нет зависимостей. Состав зависимостей других пакетов
может меняться при выпуске новой версии, поэтому его нельзя фиксировать для всех запусков.
Транзитивный обход на этом этапе не выполняется.

Поддерживается `https://pypi.org/pypi`; у короткого адреса `https://pypi.org`
путь `/pypi` добавляется автоматически. HTML-индекс `/simple` не является JSON API.

## Этап 3. Рекурсивный граф

Выберите `stage-3`. Выполните:

```sh
python src/main.py --package A --repository examples/diamond.json --test-repo
```

Результат:

```text
A -> B, C
B -> D
C -> D
D -> (нет)
```

Используется рекурсивный DFS. Каждая вершина запрашивается один раз;
общие зависимости не вызывают повторного обхода. Обратные рёбра фиксируются как циклы,
поэтому программа не зацикливается.

```sh
python src/main.py --package A --repository examples/cycle.json --test-repo
python src/main.py --package A --repository examples/diamond.json --test-repo --filter B
python src/main.py --package six --repository https://pypi.org/pypi
```

Для цикла дополнительно выводится его путь. При фильтрации B из ромба остаётся путь `A -> C -> D`.
Если потомок исключённой вершины доступен только через неё, он также не обходится;
если доступен другой путь, потомок сохраняется.

### Формат тестового репозитория

Обычный текстовый файл UTF-8 с расширением `.json`:

```json
{
  "A": ["B", "C"],
  "B": ["D"],
  "C": ["D"],
  "D": []
}
```

Все цели рёбер должны присутствовать среди ключей. Повторяющиеся ключи отклоняются,
повторяющиеся рёбра убираются. Пустой список означает отсутствие зависимостей.
В Windows при сохранении через Блокнот выберите тип «Все файлы» и имя `repository.json`,
а не `repository.json.txt`. Файл JSON не содержит Python-код.

## Этап 4. Порядок загрузки

Выберите `stage-4`. Выполните:

```sh
python src/main.py --package A --repository examples/diamond.json --test-repo
```

Результат:

```text
Порядок загрузки: D -> B -> C -> A
```

Пакет добавляется в результат после всех своих зависимостей. Общая вершина включается один раз;
независимые ветви обходятся по алфавиту. Установка пакетов не выполняется.

```sh
python src/main.py --package A --repository examples/chain.json --test-repo
python src/main.py --package A --repository examples/diamond.json --test-repo --filter B
python src/main.py --package A --repository examples/cycle.json --test-repo
```

Цепочка даёт `C -> B -> A`; ромб с фильтром B — `D -> C -> A`.
У циклического графа строгого топологического порядка нет: выводится путь цикла и возвращается код 1.
При исключении корня выводится пояснение вместо списка.

### Сравнение порядка с pip

Настоящим pip 24.2 выполнена изолированная установка локальных тестовых wheel-пакетов.
Цепочка совпала с программой: `C, B, A`. Для ромба программа выдала `D, B, C, A`,
pip — `D, C, B, A`: оба порядка допустимы, поскольку B и C независимы.
При цикле программа отказывается выдавать невозможный порядок, тогда как pip применяет свою политику
и выполняет установку. Подробные условия и пять проверенных случаев приведены в `COMPARISON.md` ветки 4.

## Этап 5. D2, изображение и ASCII

Выберите `stage-5`. Выполните:

```sh
python src/main.py --package A --repository examples/diamond.json --test-repo --ascii-tree
```

Программа печатает D2, сохраняет `output/A.d2` и `output/A.svg`,
открывает SVG стандартным браузером и по флагу дополнительно выводит дерево.
Ребро направлено от пакета к его зависимости. В изображении общая вершина одна.

```d2
direction: down
n0: "A"
n1: "B"
n2: "C"
n3: "D"
n0 -> n1
n0 -> n2
n1 -> n3
n2 -> n3
```

```text
A
|-- B
|   `-- D
`-- C
    `-- D [повтор]
```

Без `--ascii-tree` дерево не выводится. Циклические рёбра сохраняются в D2/SVG;
в дереве они отмечаются `[цикл]`, повторные раскрытия общей вершины — `[повтор]`.
Порядок загрузки этапа 4 здесь не печатается.

SVG рисуется собственным стандартным кодом из того же графа, что используется для D2,
а не внешним D2-компилятором. Установка D2 не требуется; сохранённый D2 можно передать
отдельно установленному компилятору. Папка `output/` исключена из Git.
При повторном запуске файлы выбранного корня перезаписываются.
Если браузер не открывается, файлы сохраняются: откройте SVG вручную.

### Три реальных пакета

Для актуальных метаданных публичного репозитория:

```sh
python src/main.py --package python-dateutil --repository https://pypi.org/pypi --ascii-tree
python src/main.py --package six --repository https://pypi.org/pypi --ascii-tree
python src/main.py --package pytz --repository https://pypi.org/pypi --ascii-tree
```

Для воспроизводимой демонстрации без внешнего интернета в ветках 4–5 включён снимок
реальных метаданных: python-dateutil 2.9.0.post0, six 1.17.0 и pytz 2026.4.
В первом терминале из папки проекта запустите:

```sh
python -m http.server 8000 --bind 127.0.0.1 --directory examples/pypi
```

Во втором терминале ветки 5 выполните:

```sh
python src/main.py --package python-dateutil --repository http://127.0.0.1:8000 --ascii-tree
python src/main.py --package six --repository http://127.0.0.1:8000 --ascii-tree
python src/main.py --package pytz --repository http://127.0.0.1:8000 --ascii-tree
```

Здесь не нужен `--test-repo`: программа выполняет настоящие HTTP-запросы с реальными именами.
В снимке python-dateutil зависит от six; у six и pytz зависимостей нет.
Все три изображения сформированы и отрисованы Chromium. Происхождение снимка описано
в `examples/metadata-origin.md`; это сокращённые поля из `pip inspect`, а не полный ответ PyPI.

### Сравнение с нативным выводом pip

У pip нет встроенной команды рисования графа. Для сравнения использован настоящий JSON-вывод
`python -m pip inspect`: имена и рёбра всех трёх графов совпали с метаданными тех же версий.
D2/SVG/ASCII представляют связи наглядно, а pip inspect возвращает их в JSON.
Условия, результаты и причины возможных отличий изложены в `COMPARISON.md` ветки 5.
Команды pip используются только для отдельного сравнения, не для получения графа программой.

## Сценарии запуска

Все команды выполняются из папки выбранного этапа.

```bat
run.bat --package A --repository examples\repository.json --test-repo
scripts\demo.bat
scripts\errors.bat
```

Для Linux/macOS:

```sh
sh run.sh --package A --repository examples/repository.json --test-repo
sh scripts/demo.sh
sh scripts/errors.sh
```

В ветках 4–5 сценарии `scripts/demo_real.bat` и `scripts/demo_real.sh`
содержат публичные примеры трёх пакетов. В ветке 5 демонстрация открывает изображения.
В ветках 1–2 тестовая команда выше не означает построение графа: этап 1 выводит конфигурацию,
а этап 2 сообщает, что тестовый режим получения зависимостей относится к следующему этапу.

## Проверки

В каждой ветке выполните:

```sh
python -m unittest discover -s tests -v
python tests/check_style.py
```

Результаты повторной проверки: этап 1 — 16 тестов, этап 2 — 32,
этап 3 — 51, этап 4 — 59, этап 5 — 64. Все прошли успешно.
Это 222 выполнения тестов по пяти самостоятельным версиям; часть проверок общая.
Проверка измеримых ограничений во всех ветках завершилась `OK`.

Проверяются параметры и ошибки всех опций, HTTP/JSON, кэш, нормализация имён,
тестовые данные, цепочка, ромб, общие зависимости, фильтрация, циклы и петли,
порядок загрузки, D2, SVG, дерево, запись файлов и вызов браузера.
Автотесты не требуют внешнего интернета и не открывают окон.

Соблюдаются ограничения: Python-строки до 80 символов, обычный текст до 120,
функции до 40 строк и 7 параметров, файлы до 1000 строк, измеряемая сложность до 10.
Используются docstring и snake_case; нет U+200B и unittest setUp.
Архивы, PDF, кэш, файлы IDE и результаты сборки не отслеживаются Git.
Коммиты оформляются с областью: `feat(...)`, `test(...)`, `docs(...)`, `chore(...)`.

## Ошибки и границы проверки

Коды завершения: 0 — успех, 1 — ошибка данных/сети/графа/визуализации,
2 — неверные параметры командной строки.
Проверяются недоступные файлы, структура JSON, имена, отсутствующие вершины,
сетевые ошибки, неверная кодировка и слишком глубокий рекурсивный граф.
HTTP-запрос ограничен 15 секундами и 8 МиБ ответа.

Сообщение «Ответ репозитория превышает допустимый размер» относится к HTTP-ответу
одного пакета, а не к размеру локального тестового JSON. Для небольшой сетевой демонстрации
подходит six; для повторяемого примера с зависимостью используйте снимок python-dateutil.

Программа извлекает все объявленные имена из `requires_dist`, но не выбирает версии,
не вычисляет маркеры окружения и extras. Это граф объявлений, а не полноценный решатель pip.
Последняя версия публичного пакета может отличаться от установленной или сохранённой в снимке.

В проверочной среде внешний DNS недоступен: живой запуск программы с публичным PyPI здесь
не проверен. Выполнены реальные локальные HTTP-запросы, проверки снимков реальных метаданных,
сравнение с pip и отрисовка SVG браузером. Актуальные публичные поля дополнительно просмотрены отдельно.
Нативный запуск на Windows и внешний компилятор D2 в этой среде не проверялись.
