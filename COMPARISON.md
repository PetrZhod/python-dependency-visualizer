# Сравнение визуализации с нативным выводом pip

## Условия

Проверка выполнена 12 ноября 2026 года: Python 3.13.14, pip 24.2.
Команда `python -m pip inspect` действительно выполнена для установленного окружения.
Из её вывода взяты только нужные поля трёх реальных пакетов и помещены в
`examples/pypi/<имя>/json` в структуре используемого JSON API.
Это сокращённый воспроизводимый снимок, а не полный сетевой ответ PyPI.

| Пакет | Установленная версия | Объявленные зависимости |
|---|---|---|
| python-dateutil | 2.9.0.post0 | six >=1.5 |
| six | 1.17.0 | нет |
| pytz | 2026.4 | нет |

Снимок прочитан программой через настоящий локальный HTTP-сервер, без `--test-repo`.
Для каждого корня получены D2, SVG и ASCII. SVG дополнительно открыты в headless Chromium;
проверены подписи и количество рёбер. Диаграммы рисует собственный SVG-рендерер,
а не внешний D2-компилятор.

## Полученные графы

Для python-dateutil получены две вершины и одно ребро:

```d2
direction: down
n0: "python-dateutil"
n1: "six"
n0 -> n1
```

```text
python-dateutil
`-- six
```

Для six и pytz получено по одной вершине и ни одного ребра:

```d2
direction: down
n0: "six"
```

```d2
direction: down
n0: "pytz"
```

Таким образом, наборы имён и связей во всех трёх случаях совпали с `requires_dist`
в нативном выводе pip для этих же версий. В диаграмме не показывается ограничение версии
`>=1.5`: программа исследует связи между именами, а не задачу выбора версий.

## Почему сравнение не содержит картинки самого pip

У pip нет встроенной команды визуализации графа в виде изображения или ASCII-дерева.
`pip inspect` выдаёт JSON, `pip show` — сведения и список прямых зависимостей;
это нативные способы проверить связи. Поэтому сравниваются данные с разными формами
представления, а не две несуществующие одинаковые графические команды.
Сторонний pipdeptree не использовался, чтобы не добавлять библиотеку получения зависимостей.

Для самостоятельной проверки:

```sh
python -m pip inspect > installed.json
python -m pip show python-dateutil six pytz
```

Эти команды предназначены только для сравнения. Исследуемые пакеты должны быть установлены
в проверяемом окружении, но для работы самого визуализатора установка пакетов не нужна.
Программа никогда не вызывает pip для построения графа.

## Причины возможных различий

- Программа исследует последнюю версию в указанном JSON API, а pip inspect — установленную.
- В программе не вычисляются условия Python/ОС и extras; извлекаются все объявленные имена.
- Pip разрешает ограничения версий и учитывает конкретное окружение; программа этого не делает.
- Отфильтрованные вершины и ставшие недостижимыми зависимости отсутствуют в изображении.
- В D2 и SVG общая зависимость одна; дерево помечает повтор и завершает раскрытие циклов.

Например, публичные метаданные python-dateutil 4.0.0 при проверке объявляли tzdata,
тогда как снимок установленной 2.9.0.post0 объявляет six. Это различие версий, не ошибка DFS.

## Границы проверки

Внешний DNS в среде запуска недоступен: живой запуск программы с публичным PyPI здесь
не проверен. Выполнены реальные локальные HTTP-запросы со снимками метаданных;
актуальные публичные поля дополнительно просмотрены отдельно.
Автотесты проверяют вызов браузера с подменой, а SVG отдельно отрисованы Chromium.
Поведение стандартного браузера Windows и внешний D2-компилятор здесь не проверялись.
